# OperatingSystem — 批处理作业调度算法模拟

操作系统课程实验项目：模拟多道批处理系统中「输入井 → 内存 → CPU」的多级调度流程，通过组合不同的作业调度与进程调度算法，对比分析各调度策略对系统性能（平均周转时间、平均带权周转时间）的影响。

## 项目背景

在多道批处理系统中，作业提交后并不会立即执行，而是要经过多级调度：

1. **作业调度（高级调度）**：从输入井中挑选作业调入内存，决定作业进入内存的次序；
2. **进程调度（低级调度）**：从内存中就绪的进程里选出下一个占用 CPU 的进程，决定 CPU 的执行次序。

不同的调度策略会显著影响作业的周转时间、带权周转时间和系统吞吐量。本实验以离散时间片（每分钟一步）推进仿真，实现并对比多种经典调度算法，最终以平均周转时间与平均带权周转时间作为性能评价指标。

## 功能

- **作业调度算法（Job Scheduling）**
  - `FCFS` — 先来先服务
  - `SJF` — 短作业优先
  - `HRN` — 最高响应比优先
  - `HPF` — 最高优先级优先（数字越小优先级越高）
- **进程调度算法（Process Scheduling）**
  - `FCFS` — 先来先服务
  - `SPF` — 短进程优先
  - `SRT` — 最短剩余时间优先（可抢占）
  - `HPF` — 最高优先级优先
- **调度全流程模拟**：作业进入输入井、调入内存、占用 CPU、运行完成的全过程；
- **性能指标计算**：逐个作业输出周转时间、带权周转时间，并汇总平均周转时间与平均带权周转时间。

## 编译 & 运行

### 方式一：VS Code + CMake Tools（推荐）

1. 用 VS Code 打开项目，安装 `CMake Tools` 与 `C/C++` 插件；
2. 状态栏确认生成器为 `MinGW Makefiles`、构建目录为 `build`（已写入 `.vscode/settings.json`）；
3. 底栏点击 **Build**，或直接按 `F5` 调试运行。

> 程序为交互式输入，调试配置已开启独立控制台窗口（`externalConsole: true`）。

### 方式二：命令行 CMake

```bash
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
./build/OperatingSystem.exe
```

### 方式三：直接编译单文件

```bash
g++ -std=c++20 -g src/main.cpp -o OperatingSystem.exe
./OperatingSystem.exe
```

## 使用示例

程序启动后按提示依次输入调度配置与作业信息：

```
设置内存中最多等待处理的进程数: 3
设置系统作业调度算法: FCFS
设置系统进程调度算法: SPF
输入待处理的作业数: 6
JOB1:
到达时间: 8:00
估计运行时间: 30
JOB2:
到达时间: 8:20
估计运行时间: 10
JOB3:
到达时间: 8:40
估计运行时间: 50
JOB4:
到达时间: 9:00
估计运行时间: 20
JOB5:
到达时间: 9:10
估计运行时间: 40
JOB6:
到达时间: 9:30
估计运行时间: 10
```

程序运行结束输出调度结果表格（数值为真实运行结果）：

| 作业 | 到达时间 | 估计运行时间（min） | 开始时间 | 结束时间 | 周转时间（min） | 带权周转时间 |
| :--: | :--: | :--: | :--: | :--: | :--: | :--: |
| JOB1 | 8:00 | 30 | 8:00 | 8:40 | 40 | 1.33333 |
| JOB2 | 8:20 | 10 | 8:20 | 8:30 | 10 | 1 |
| JOB3 | 8:40 | 50 | 8:40 | 10:40 | 120 | 2.4 |
| JOB4 | 9:00 | 20 | 9:00 | 9:20 | 20 | 1 |
| JOB5 | 9:10 | 40 | 9:20 | 10:10 | 60 | 1.5 |
| JOB6 | 9:30 | 10 | 9:30 | 9:40 | 10 | 1 |

平均周转时间: 43.3333；平均带权周转时间: 1.37222

**输入说明：**

- `到达时间` 按 `H:MM` 格式输入（如 `8:05`），程序内部会换算为分钟；
- 当作业调度或进程调度算法选择 `HPF` 时，每个作业需额外输入 `优先级`，且**数字越小优先级越高**；
- `设置内存中最多等待处理的进程数` 表示内存中最多可同时容纳的进程数（含正在 CPU 上执行的进程）。

## 实现要点

- 每个作业用 `Job` 结构体记录：到达时间、估计运行时间、优先级、状态（未进入 / 输入井 / 内存 / CPU / 完成）、进入内存时间、开始时间、已运行时间、结束时间、周转时间与带权周转时间；
- `Dispatch()` 以 `currentTime` 逐分钟推进，在每一步依次完成「送入输入井 → 作业调度调入内存 → 进程调度占用 CPU → 统计完成情况」；
- 各调度算法封装为独立的 `FCFS / SJF / HRN / HPF / SPF / SRT` 函数，按算法规则返回被选中作业的位置。
